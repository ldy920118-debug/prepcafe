# 수업 개발 계획

**상태:** 사용자 확인을 받은 100분 범위 감축안과 4시간 수업 계획입니다. 시간은 모두 추정치입니다. EPIC 1은 2026-09-28 사용자 화면 확인을 받아 완료했습니다. EPIC 2는 구현과 자동 검사를 마쳤으며, 사용자 화면 확인 전까지 완료로 표시하지 않습니다.

## 현재 진행 상태

| EPIC | 진행 상태 |
|---|---|
| EPIC 1. 기록을 저장하고 바로잡기 | 완료 — 2026-09-28 사용자 확인 |
| EPIC 2. 메뉴 수익성과 하루 손익 확인 | 구현·자동 검사 완료, 사용자 화면 확인 대기. 아직 완료 처리하지 않음 |
| EPIC 3. 재료 잔량과 흐름 연결 | 미착수 |

## 전체 작업 순서와 나눈 이유

### 기준 문서와 범위 조정

- 요청된 `docs/01_PRD.md`는 작업 폴더에 없습니다. [실제 PRD](../data/docs/docs_PRD.md), [FRD](02_FRD.md), [TRD](03_TRD.md), `data/design/stitch_cafe_daily_closing_app/` 시안을 기준으로 했습니다.
- 이전 사용자 결정에 따라 시안의 예시 목록을 사용하고 첨부 판매 이력은 미리 채우지 않습니다. PRD 초안의 첨부 이력 샘플 시작 문구보다 이후 결정이 우선합니다. 첨부 XLSX와 JSON은 같은 자료이므로 어느 쪽도 이번 시작 데이터로 가져오지 않습니다.
- 사용자가 승인한 수업 감축안에 따라 수업 중에는 **일간** 손익만 제공합니다. 주·월 조회와 FRD에 추가 승인된 일일 마감·잠금·재고 이월·전표 인쇄는 수업 후로 이동합니다. 영향은 주·월 비교와 날짜 확정 절차를 수업 중에는 사용할 수 없다는 점입니다.
- 수업 중 남기는 흐름은 판매 입력·수정·삭제 → 메뉴 수익성 → 날짜별 비용을 반영한 일 손익 → 재료 잔량입니다. 비용 기록도 입력·수정·삭제하고, 데이터 저장·기본 오류 처리·자동 검사와 화면 확인은 감축하지 않습니다.
- 계산의 검증 가능한 예시가 필요하므로 FRD의 추천 계산을 수업 검증 기본안으로 채택합니다. 이는 첨부 원자료의 실제 기록·원가를 뜻하지 않습니다.

## EPIC 1. 기록을 저장하고 바로잡기 — 완료 · 예상 50분

### 포함 Story

1. 시안 예시 자료로 시작하고 저장 상태를 확인한다 — 15분
2. 판매 기록을 입력·수정·삭제한다 — 20분
3. 비용 기록을 입력·수정·삭제한다 — 15분

### EPIC 완료 기준

- 시안의 메뉴 8개·채널 3개·재료 11개가 보이고 첨부 파일의 과거 판매 기록은 섞이지 않습니다.
- 판매와 비용 기록을 각각 입력·수정·삭제할 수 있고, 잘못된 필수값을 저장하지 않습니다.
- 새로고침하거나 화면을 다시 열어도 저장한 값이 남습니다.
- 자동 검사가 성공하고, 사용자가 판매·비용 화면에서 직접 결과를 확인합니다.

### Story 1. 시안 예시 자료로 시작하고 저장 상태를 확인한다 — 15분

- **사용자가 할 수 있는 일:** 운영 화면을 열어 시안 예시 메뉴·채널·재료와 데모 거래를 확인합니다.
- **자동 검사:** 초기 자료가 중복 삽입되지 않는지, 첨부의 6,112건 판매 이력이 들어오지 않는지, 데모 저장 후 다시 읽을 때 같은 자료가 반환되는지 확인합니다.
- **화면에서 확인할 행동과 예상 결과:** 시작 화면에서 메뉴 8개, 채널 3개, 재료 11개를 확인하고 새로고침합니다. 목록이 그대로 남으며 첨부 과거 이력은 표시되지 않습니다. 수치가 서로 맞지 않는 기존 시안 대시보드 합계는 정답으로 사용하지 않습니다.

### Story 2. 판매 기록을 입력·수정·삭제한다 — 20분

- **사용자가 할 수 있는 일:** 날짜·채널·메뉴·수량·실제 단가·할인·실제 결제 수수료를 입력하고, 저장된 판매를 수정하거나 삭제합니다. 수수료율을 임의로 계산하지 않고 실제 금액을 입력합니다.
- **자동 검사:** 수량이 1 이상인지, 필수 참조값이 있는지, 할인액이 총 판매액 이하인지 검사합니다. 저장·수정·삭제가 재조회 후에도 유지되고 동일 거래를 재시도해 중복 생성하지 않는지 확인합니다. 레시피·원가 자료가 없을 때 원가 0원으로 오인되지 않는지 확인합니다.
- **화면에서 확인할 행동과 예상 결과:** 데모 열린 날짜에 아메리카노 2개, 개당 4,500원, 할인 1,000원을 입력합니다. 순매출 미리보기와 저장된 기록 모두 **8,000원**입니다. 할인액을 고친 뒤 새로고침해도 수정값이 남고, 삭제 후에는 행이 사라집니다.

### Story 3. 비용 기록을 입력·수정·삭제한다 — 15분

- **사용자가 할 수 있는 일:** 날짜·비용 항목·비용 구분·금액을 입력하고 저장된 기록을 수정하거나 삭제합니다. 비용 구분은 시안 예시 목록을 사용합니다.
- **자동 검사:** 날짜·항목·금액의 필수값과 금액 형식을 검증합니다. 저장·수정·삭제가 재조회 후 유지되고, 날짜별 비용만 실제 손익에 반영되는지 확인합니다. 월 비용 계획을 다시 합산하지 않습니다.
- **화면에서 확인할 행동과 예상 결과:** 판매와 같은 데모 날짜에 소모품 비용 **1,000원**을 입력합니다. 비용 목록에 날짜와 금액이 보이고 새로고침 뒤에도 남습니다. 수정·삭제 결과가 이후 일 손익 화면에도 반영됩니다.

## EPIC 2. 메뉴 수익성과 하루 손익 확인 — 사용자 확인 대기 · 예상 30분

### 포함 Story

4. 메뉴별 직접 수익성을 확인한다 — 18분
5. 선택한 날짜의 실제 손익을 확인한다 — 12분

### EPIC 완료 기준

- 같은 저장 판매 기록을 메뉴 수익성과 일 손익 양쪽에서 사용합니다.
- 직접 비용에는 메뉴와 직접 연결되는 재료·포장·결제 수수료만 반영하고 임차료·인건비를 메뉴별로 나누지 않습니다.
- 실제 손익에는 날짜별 비용만 반영합니다. 수정·삭제 후 분석 화면도 갱신됩니다.
- EPIC 1의 판매·비용 CRUD 자동 검사를 다시 실행해도 통과하고, 사용자가 계산 결과를 화면에서 확인합니다.

### Story 4. 메뉴별 직접 수익성을 확인한다 — 18분

- **사용자가 할 수 있는 일:** 메뉴 수익성 화면에서 선택 기간의 메뉴별 매출·직접 비용·공헌이익을 비교합니다. 판매 기록 전체의 재료·포장 원가와 실제 결제 수수료를 합산합니다. 공헌이익은 매출에서 직접 비용을 뺀 금액입니다.
- **원가 입력 기준:** 재료·포장 원가는 판매 묶음 전체 금액으로 입력하고, 개당 값은 판매 수량으로 나눈 평균을 표시합니다. 두 비용을 모르면 둘 다 비워 둡니다. 이전 형식의 판매 기록과 원가 미입력 메뉴는 0원으로 간주하지 않고 `자료 확인 필요`를 표시합니다.
- **자동 검사:** 테스트 판매에 재료비·포장비·실제 결제 수수료를 적용하고 직접 비용 합계, 공헌이익, 공헌이익률을 확인합니다. 순매출이 0일 때 비율을 0%로 오인시키지 않는지 확인합니다. 공통 비용을 메뉴 직접 비용에 넣지 않는지 확인합니다.
- **화면에서 확인할 행동과 예상 결과:** 앞 Story의 판매를 사용하고 검증용 직접 비용을 재료비 **1,200원**, 포장비 **200원**, 수수료 **100원**으로 둡니다. 직접 비용은 **1,500원**, 공헌이익은 **6,500원**, 공헌이익률은 **81.25%**입니다. 화면을 새로고침해도 같습니다.

### Story 5. 선택한 날짜의 실제 손익을 확인한다 — 12분

- **사용자가 할 수 있는 일:** 기간 손익 화면에서 일간을 선택해 해당 날짜의 매출·직접 비용·날짜별 비용·손익을 확인합니다.
- **자동 검사:** 일 손익이 순매출 − 직접 비용 − 날짜별 비용으로 계산되는지 확인합니다. 월 비용 계획이 중복 합산되지 않는지, 기록이 없는 날짜와 실제 0원 기록이 구분되는지 확인합니다.
- **화면에서 확인할 행동과 예상 결과:** 같은 날짜에 앞선 Story의 값을 사용합니다. **8,000원 − 1,500원 − 1,000원 = 5,500원**이 손익으로 표시됩니다. 날짜별 비용을 수정하면 새로고침 뒤에도 손익이 갱신되어 유지됩니다.

## EPIC 3. 재료 잔량과 흐름 연결 — 미착수 · 예상 20분

### 포함 Story

6. 재료 입고·폐기·실사를 기록하고 잔량을 확인한다 — 20분

### EPIC 완료 기준

- 사용자가 입고·폐기와 실제 센 재고량을 기록할 수 있습니다.
- 판매 레시피 사용량, 입고, 폐기, 실사 결과가 잔량에 정확히 반영됩니다.
- 저장 및 오류 검증 자동 검사가 통과하고, 사용자는 화면에서 잔량을 확인합니다.
- EPIC 1·2 검사를 다시 실행해 기존 판매·비용 입력, 메뉴 수익성, 일 손익이 계속 맞는지 확인합니다.
- 마지막으로 판매 입력부터 메뉴 수익성·일 손익·재료 잔량까지 하나의 저장 기록으로 연결해 확인합니다.

### Story 6. 재료 입고·폐기·실사를 기록하고 잔량을 확인한다 — 20분

- **사용자가 할 수 있는 일:** 재료와 날짜를 선택해 입고·폐기 수량을 입력하고, 실사 시 실제로 센 수량을 입력합니다. 입고와 폐기는 양수로 입력하고 유형에 따라 증감 방향을 적용하며, 실사에는 차이값이 아니라 실제 수량을 입력합니다.
- **자동 검사:** 잔량이 기초 재고 + 입고 − 레시피 판매 사용량 − 폐기 ± 실사 조정으로 계산되는지 확인합니다. 재료별 기준 단위가 다르면 자동 환산하지 않고 거부합니다. 음수 잔량은 판매 기록을 지우지 않고 부족 경고와 잔량을 표시합니다. 공백과 0은 구분합니다.
- **화면에서 확인할 행동과 예상 결과:** 검증용 원두 재고를 기초 **100g**으로 둡니다. **50g 입고**, 아메리카노 2개 판매로 **20g 사용**(1개당 10g), **3g 폐기**를 기록하면 실사 전 이론 잔량은 **127g**입니다. 실제 재고 **122g**을 입력하면 실사 조정은 **−5g**, 최종 잔량은 **122g**입니다. 새로고침 뒤에도 거래 내역과 잔량이 유지됩니다.

## 수업 후 확장 기능과 남은 확인 사항

### 수업 후 확장 기능

- **승인된 감축으로 수업 후 이동:** 주간·월간 손익 조회, 일일 마감 확정·기록 잠금·다음 날 재고 이월·전표 인쇄. 해당 기능 완료 전에는 날짜 마감과 잠금이 제공되지 않습니다.
- **PRD·FRD의 기존 확장:** 분기·반기·연간 조회, 예상 손익, 엑셀 양식 내려받기와 가져오기, 백업·복원, 부족 재료 발주 참고량.
- POS·결제·회계 연동, 여러 매장 관리, 자동 발주 전송은 제외 상태를 유지합니다.

### 계획에 적용한 추천 기준과 남은 확인 사항

- FRD의 숫자 예시는 자료 원본의 실적이 아닌 수업 검증용 가상 값으로 적용했습니다. 2개 × 4,500원 − 1,000원 할인 = 순매출 8,000원; 직접 비용 1,200원 + 200원 + 100원 = 1,500원; 공헌이익 6,500원; 날짜별 비용 1,000원을 뺀 일 손익 5,500원입니다.
- 메뉴 직접 비용의 테스트 단가와 데모 거래 수치는 시안의 일치하지 않는 대시보드 합계를 정답으로 복사하지 않고 서로 맞게 만든 검증 값입니다. 실제 운영 원가 자료로 해석하지 않습니다.
- 사용자가 선택한 시안 예시 목록은 사용하되, 계산 검증 자료는 일관된 레시피·재료 단위로 구성합니다. g·ml·개·kg·캔·세트 사이 자동 변환은 하지 않습니다.
- 비용 구분은 시안의 소모품비·배달 플랫폼 수수료·긴급 식자재 구매·수선유지 및 위생비·기타 잡비 예시를 사용합니다. 동일 재료 구매를 비용과 재고 입고에 둘 다 기록하면 이중 계산될 수 있으므로 검증 데이터에서는 구매 비용을 날짜별 일반 비용에 중복 입력하지 않습니다.
- 구현 전 실제 결제 수수료는 거래별 실제 금액을 입력하고 수수료율을 자동 추정하지 않는다는 기준을 확인합니다. 레시피·재료 단가가 없거나 채널에 적용되지 않을 때 판매 저장은 허용하되 수익성·재고 결과를 미계산으로 표시하는 권고안을 사용하며, 전체 합계에 계산 누락 표시를 남깁니다.
- TRD에 제안됐으나 PRD·FRD에서 확정되지 않은 로그인·RLS 사용자 정책, 운영용 GitHub 저장소 공개 범위는 수업 기능에 추가하지 않습니다. 실제 기록을 넣는 운영 배포 전에 접근 보호를 승인·구성해야 하며, 그 전에는 가상 데모 자료만 사용합니다.
