# 기능 요구사항 문서 (FRD) 초안

## 문서 기준과 상태 표시

- 요청된 `docs/01_PRD.md` 파일은 작업 폴더에서 찾지 못했습니다. 확인 가능한 PRD인 `data/docs/docs_PRD.md`와 `data/design/stitch_cafe_daily_closing_app/`의 시안 설명·화면·HTML을 기준으로 작성했습니다.
- **확정**은 PRD 또는 대화에서 확인한 범위입니다. **제안**은 작동 방식을 구체화하기 위해 제시하는 계산·예외 처리이며, 이후 검토가 필요합니다. **미정**은 PRD와 시안만으로 정할 수 없어 임의로 확정하지 않은 내용입니다.
- 사용자는 시안의 예시 목록을 기준으로 하고 첨부 파일의 판매 이력은 시작 자료로 미리 넣지 않기로 했습니다. 따라서 시안에 있는 메뉴·재료·채널은 데모 목록이며, 첨부 매장 기록의 실제 값으로 간주하지 않습니다.
- 사용자는 시안의 일일 마감 기능을 포함하기로 했습니다. 마감 확정, 기록 잠금, 다음 날 재고 이월, 마감 전표 출력이 이 범위에 포함됩니다.
- 메뉴 수익성은 재료·포장·결제처럼 메뉴와 직접 연결되는 비용만 반영하고, 임차료·인건비 같은 공통 비용은 메뉴별로 배분하지 않습니다. 실제 기간 손익은 날짜가 있는 비용 기록을 사용하며 월 비용 계획을 다시 더하지 않습니다.
- 수업 MVP는 일·주·월 조회, 판매·비용 입력과 수정·삭제, 메뉴 수익성, 실제 손익, 재고 기록·잔량, 저장과 기본 검증입니다. 분기·반기·연간 조회, 전망, 엑셀 양식·가져오기, 백업·복원, 발주 참고는 수업 후 확장입니다.
- 아래 계산 방식은 초안 제안입니다. PRD에 없던 POS 연동, 여러 매장 관리, 알림, 영수증 첨부, 결제 수단 관리 기능은 새 요구사항으로 넣지 않았습니다.

## 전체 사용 순서

1. 시안 예시 자료가 표시된 상태로 매장 관리 화면을 엽니다. 시안의 날짜·수치도 데모 예시이며 첨부 파일의 이력은 미리 채우지 않습니다.
2. 일·주·월 기간을 선택해 대시보드와 판매·비용 기록을 봅니다.
3. 판매 기록을 입력하고, 실제 가격과 할인 처리를 적용한 매출 미리보기를 확인한 뒤 저장합니다.
4. 비용 기록을 입력하거나 기존 판매·비용 기록을 수정·삭제합니다.
5. 메뉴별 수익성에서 메뉴별 직접 비용과 공헌이익을 비교합니다. 공헌이익은 매출에서 메뉴에 직접 붙는 비용을 뺀 값입니다.
6. 기간 손익에서 해당 기간의 실제 매출·직접 비용·날짜별 비용 기록을 확인합니다.
7. 재료 입고·폐기·실사를 기록하고, 레시피 판매 차감과 조정 후 잔량을 확인합니다.
8. 일일 마감 전 누락과 재고 상태를 검토하고, 마감 전표를 출력한 뒤 확정합니다. 확정 후 해당 날짜 기록은 잠기고 재고가 다음 날짜의 기초 재고로 넘어갑니다.
9. 수업 후에는 더 긴 기간 조회, 예상 손익, 엑셀 파일, 백업·복원, 발주 참고 기능을 사용합니다.

## 자료와 시안에서 확인한 주의사항

- 첨부 원자료의 실제 기록은 2025-07-01~2026-09-18, 금액은 원화·부가세 제외, 재료 단위는 g·ml·개입니다. 달력은 2026-09-30까지 있지만 2026-09-18 이후는 미마감 날짜이므로 판매 0으로 처리하지 않습니다. 이번 시작 화면에는 해당 판매 이력을 불러오지 않으며, 향후 가져오기를 만들 때 이 주의사항을 적용합니다.
- 첨부 엑셀과 JSON은 같은 기록입니다. 나중에 자료를 가져올 때 둘 다 입력하지 않도록 안내해야 합니다. 판매는 주문별 자료가 아니라 일자·메뉴·채널별 합계이며 ID는 같은 대상을 가리킵니다.
- 첨부 레시피의 수량은 메뉴 1개당 사용량입니다. 구매용량 가격과 혼동하지 않습니다. 레시피 적용 채널이 비어 있으면 모든 채널, 포장으로 표시된 재료는 포장 판매에만 적용합니다. 판매 당시 레시피 버전을 보존해야 합니다.
- 첨부 자료의 월 비용 계획과 날짜별 비용 기록은 같은 비용의 월 단위·일 단위 표현입니다. 선택된 MVP 기준에 따라 실제 손익에는 날짜별 비용 기록만 사용하고 월 계획을 더하지 않습니다.
- 시안의 예시 자료는 첨부 자료와 다릅니다. 예를 들어 시안 채널은 매장 POS·배달·테이크아웃이고, 메뉴는 아메리카노·카페라떼·바닐라빈 라떼·콜드브루·자몽 에이드·말차 라떼·플레인 스콘·당근 케이크입니다. 시안 재료에는 kg·캔·세트 단위도 보이지만 첨부 자료는 g·ml·개를 씁니다. 선택한 시안 목록을 데모로 사용하되 첨부 자료를 그 목록에 임의로 이름 바꾸거나 합치지 않습니다.
- 시안에 나온 대시보드 수치는 계산의 정답으로 쓰지 않습니다. 메뉴별 예시 합계와 대시보드 공헌이익이 서로 맞지 않고, 케이크 행의 수량×가격과 표시 매출도 다릅니다. 아래 확인 예시는 서로 맞도록 작은 값으로 새로 계산했습니다.
- 시안 HTML의 제출 처리기는 실제 저장 대신 모달을 닫고 성공 알림을 띄우는 시뮬레이션입니다. FRD에서는 실제 저장, 목록 반영, 재계산, 오류 처리를 요구합니다.
- ‘매장 POS’는 시안 데모에서 판매 채널 이름으로만 다룹니다. 외부 POS 연동은 PRD에서 제외한 범위이므로 자동 가져오기 기능으로 해석하지 않습니다.
- 시안의 매장 지점·사용자 프로필·알림, 영수증 첨부, 결제 수단 선택은 PRD에서 기능으로 확인되지 않았습니다. 현재 FRD의 필수 기능으로 넣지 않습니다. 비용 분류 항목도 시안과 첨부 자료의 범주가 달라 실제 사용할 목록은 미정입니다.

## 기능 요구사항

### 1. 시안 예시 자료와 초기 화면

#### 사용자가 하는 일

사용자는 화면에 표시된 메뉴·재료·판매·비용 데모를 통해 조회 흐름을 확인하고 새 기록을 입력합니다.

#### 입력

처음에는 사용자가 입력하지 않습니다. 시안에서 제시한 예시 메뉴 8개, 채널 3개, 재료 11개와 화면의 데모 기록이 표시됩니다. 데모 날짜로 보이는 2026-09-18은 실제 오늘이나 첨부 기록의 마감일로 고정하지 않습니다.

#### 프로그램이 하는 일

데모 화면의 숫자를 동일한 거래 사실로 간주하지 않고, 각 기록을 기준으로 화면 요약을 계산합니다. 수량이나 금액이 서로 맞지 않는 데모 자료는 수업 검증 예시로 사용하지 않습니다.

#### 화면과 파일에 나오는 결과

대시보드에는 선택 기간의 판매·비용·수익성·재고 요약을 표시합니다. 초기 화면에는 첨부 과거 기록을 가져온 것처럼 보이는 메시지를 표시하지 않습니다. 파일 출력은 없습니다.

#### 오류나 예외가 있을 때의 동작

데모에 메뉴 레시피나 단가가 빠져 계산할 수 없으면 해당 수익성 값을 0원으로 표시하지 않고 ‘계산 자료 없음’으로 표시합니다. 실제 입력 기록이 없는 기간도 빈 기록과 실제 0원을 구분합니다.

#### 직접 확인할 방법

초기 화면에서 메뉴·채널·재료가 시안 예시 목록으로 표시되는지, 첨부 파일의 과거 날짜별 기록이 섞여 나오지 않는지 확인합니다.

### 2. 판매 기록 입력·수정·삭제

#### 사용자가 하는 일

상단의 ‘판매 입력’ 또는 기록 화면의 ‘판매 기록 추가’를 눌러 판매를 입력합니다. 기존 목록의 수정·삭제 버튼으로 기록을 고치거나 지웁니다.

#### 입력

- 시안에서 확인되는 입력: 판매 일자, 판매 채널, 레시피 버전, 메뉴, 판매 수량.
- 계산 정확성을 위한 제안 입력: 실제 판매 단가, 할인 금액, 결제 수수료. 메뉴 선택 시 기본 단가를 불러오되 실제 가격·할인·수수료를 기록할 수 있게 합니다. 시안 입력창에는 실제 단가·할인·수수료 입력란이 없어 추가 확인이 필요한 제안입니다.
- 판매 채널 데모 값은 매장 POS(대면), 배달의민족/쿠팡이츠, 테이크아웃 창구입니다. POS 자동 연동은 하지 않습니다.

#### 프로그램이 하는 일

제안 계산은 다음과 같습니다.

- 순매출 = 판매 수량 × 실제 단가 − 할인 금액
- 예: 4,500원짜리 2개에서 1,000원 할인하면 2 × 4,500 − 1,000 = **8,000원 순매출**입니다.
- 저장하면 판매 기록표에 일자·채널·메뉴·수량·단가·할인·순매출·레시피 버전을 반영하고, 메뉴 수익성·기간 손익·재고 조회를 다시 계산합니다.
- 선택된 레시피 버전과 판매 채널에 맞춰 재료 사용량을 재고에서 차감합니다. 메뉴의 적용 채널이 비어 있으면 모든 채널에 적용하고, 포장 전용 재료는 포장 판매에만 적용합니다.
- 단가·할인·수수료의 필드별 확정 방법과 수수료율 자동 계산 여부는 미정입니다. 수수료율을 임의로 만들어 계산하지 않습니다.

#### 화면과 파일에 나오는 결과

입력창에는 저장 전 매출 미리보기를 표시합니다. 저장 후 판매 기록표에 행이 나타나고, 대시보드·메뉴 분석·기간 손익·재고 잔량에 변경이 반영됩니다. 수업 MVP에는 판매 파일 출력이 없습니다.

#### 오류나 예외가 있을 때의 동작

- 일자·채널·메뉴·수량 등 필수값이 없거나 수량이 1 미만이면 저장하지 않고 입력창에 오류를 표시합니다. 값은 유지해 수정할 수 있게 합니다.
- 할인액이 판매 총액보다 크거나, 금액·수량 형식이 유효하지 않으면 저장하지 않습니다.
- 같은 일자·메뉴·채널 기록이 이미 있을 때는 중복 입력을 알리고 기존 행을 수정하도록 제안합니다. 자동으로 합치거나 중복 저장하지 않는 것이 제안 기준입니다.
- 레시피 버전이 없거나 채널에 적용되지 않는 재료가 발견되면 판매 기록을 임의로 원가 0 처리하지 않습니다. 수익성·재고에 ‘레시피 확인 필요’를 표시합니다. 실제 판매를 기록해야 하는 상황에서 저장까지 막을지는 미정입니다.
- 마감 확정된 일자의 기록은 수정·삭제하지 못하게 하고 잠금 상태를 안내합니다. 마감 취소·재개 기능은 시안에 없으므로 포함하지 않습니다.

#### 직접 확인할 방법

4,500원 메뉴 2개와 할인 1,000원을 입력해 8,000원이 미리보기와 저장 행에 나타나는지 확인합니다. 이후 할인액을 수정하면 메뉴·기간 합계가 한 번만 바뀌고, 삭제하면 해당 매출과 레시피 재고 차감이 함께 사라지는지 확인합니다.

### 3. 비용 기록 입력·수정·삭제

#### 사용자가 하는 일

‘비용 전표’ 또는 ‘비용 전표 등록’을 눌러 비용을 기록합니다. 기록표에서 기존 비용을 수정·삭제합니다.

#### 입력

- 시안에서 확인되는 입력: 지출 일자, 비용 구분, 항목명/적요, 지출 금액.
- 시안에는 결제 수단 선택과 영수증 첨부도 보이지만 PRD에 없는 추가 항목이므로 이번 기능 요구사항에는 포함하지 않습니다.
- 실제 손익은 날짜별 비용 기록만 사용합니다. 월 비용 계획을 일별 기록에 다시 더하지 않습니다. 날짜별 비용은 금액과 날짜를 확인할 수 있어야 합니다. 사용할 비용 구분 목록은 미정입니다.

#### 프로그램이 하는 일

날짜별 비용 기록의 금액을 해당 일자·선택 기간 손익에 반영합니다. 예를 들어 5,000원과 3,000원의 날짜별 비용을 입력하면 해당 기간 비용 합계는 8,000원입니다. 수정·삭제하면 손익 요약도 다시 계산합니다.

#### 화면과 파일에 나오는 결과

비용 입력은 ‘비용 지출 전표’ 표에 날짜·항목·구분·금액으로 보입니다. 기간 손익에는 날짜가 선택 기간에 포함된 비용 기록의 합계를 한 번 반영합니다. MVP 비용 파일 출력은 없습니다.

#### 오류나 예외가 있을 때의 동작

- 일자, 항목명, 금액 등 필수값이 없거나 금액이 유효하지 않으면 저장하지 않고 해당 입력을 안내합니다.
- 비용 기록에 재료 구매를 입력하면서 동일 구매를 재고 입고에도 기록하면 이중 반영될 수 있습니다. 재료 구매를 비용 기록으로만 다룰지 재고 입고로도 관리할지, 두 장부 간 비용 처리 기준은 미정입니다. 시스템은 이 중복 가능성을 안내해야 합니다.
- 마감된 날짜의 비용은 수정·삭제할 수 없고 잠금 상태를 안내합니다.
- 시안의 ‘월세·정규 급여는 일일 비용에 입력하지 말고 월 계획에서 자동 배분’ 안내는 사용자가 고른 날짜별 비용 기준과 다릅니다. 이 문구는 MVP 동작으로 확정하지 않으며, 화면에서 그대로 사용할지 수정할지 미정입니다.

#### 직접 확인할 방법

5,000원과 3,000원 비용 기록을 만들어 비용 합계가 8,000원인지 봅니다. 하나를 4,000원으로 수정하면 9,000원이 되는지, 삭제 후에는 삭제된 기록이 합계에서 빠지는지 확인합니다.

### 4. 메뉴별 수익성 분석

#### 사용자가 하는 일

‘메뉴별 수익성 분석’ 탭 또는 대시보드의 ‘마진 분석표’를 눌러 메뉴를 비교합니다.

#### 입력

선택한 일자 또는 기간, 메뉴별 판매 기록, 해당 판매의 레시피 버전, 메뉴 직접 비용 자료를 사용합니다. 화면에서 보이는 메뉴는 시안 예시입니다.

#### 프로그램이 하는 일

이전 대화에서 확정한 범위대로 메뉴 직접 비용만 반영합니다. 계산식은 구현 전 제안으로 표시합니다.

- 메뉴 공헌이익 = 메뉴 순매출 − 재료 원가 − 포장 원가 − 결제 수수료
- 공헌이익률 = 메뉴 공헌이익 ÷ 메뉴 순매출 × 100
- 예: 순매출 8,000원, 재료 1,200원, 포장 200원, 수수료 100원이면 직접 비용 1,500원, 공헌이익 **6,500원**, 공헌이익률 **81.25%**입니다.
- 임차료·인건비 등 공통 비용은 메뉴마다 나누지 않습니다. 전체 기간 손익에서 따로 봅니다.
- 판매 당시 레시피 버전과 가격 스냅샷을 유지합니다. 새 판매에 사용할 레시피 재료가격의 기준일·원가 방식은 미정이므로 임의의 구매가격을 선택하지 않습니다.

#### 화면과 파일에 나오는 결과

화면 표에 메뉴명, 판매가, 메뉴 직접 비용, 개당 공헌이익, 공헌이익률, 선택 기간 판매 수량, 기간 공헌이익을 표시합니다. 높은 공헌이익 또는 비율을 비교할 수 있도록 정렬을 제공합니다. 메뉴 분석 파일 출력은 MVP에 없습니다.

#### 오류나 예외가 있을 때의 동작

- 분모인 순매출이 0이면 비율을 계산하지 않고 ‘계산 불가’로 표시합니다.
- 가격·레시피·비용 자료가 없거나 적용 버전을 찾지 못하면 값을 0으로 대체하지 않고 ‘자료 확인 필요’로 표시합니다.
- 공통 비용을 메뉴별로 자동 배분하지 않습니다.
- 설계 시안의 공헌이익 표시값은 일부 합계와 맞지 않으므로 검증 정답으로 사용하지 않습니다.

#### 직접 확인할 방법

위 예시를 입력해 직접 비용 1,500원, 공헌이익 6,500원, 비율 81.25%가 표시되는지 계산기로 확인합니다. 임차료 비용을 추가해도 개별 메뉴 결과는 변하지 않고 기간 손익만 변하는지 확인합니다.

### 5. 일·주·월 실제 손익 조회

#### 사용자가 하는 일

‘기간 손익 & 원부재료 잔량’ 탭에서 일간·주간·월간을 선택합니다. 선택한 기간의 실제 기록을 확인합니다.

#### 입력

조회 기간과 저장된 판매·비용·재고 기록이 입력값입니다. 시안에는 2026-09-18 일간, 2026-09-12~09-18 주간, 2026년 9월 누적 예가 있습니다. 이는 기간 표기의 예시일 뿐 회계 주간 경계가 확정되었다는 뜻은 아닙니다.

#### 프로그램이 하는 일

날짜별 실제 비용 기록만 사용한다는 선택을 반영한 계산 제안입니다.

- 기간 손익 = 기간 순매출 − 기간 메뉴 직접 비용 − 기간 날짜별 비용 기록
- 예: 순매출 8,000원, 메뉴 직접 비용 1,500원, 날짜별 비용 1,000원이면 실제 영업 손익은 **5,500원**입니다.
- 월 비용 계획을 위 계산에 다시 더하지 않습니다. 메뉴 직접 비용에는 확정된 범위대로 재료·포장·결제 수수료를 반영합니다.
- 기간이 아직 끝나지 않았거나 영업 마감이 확인되지 않은 날짜는 0원으로 단정하지 않고 ‘누적/미마감’ 상태를 표시합니다.

#### 화면과 파일에 나오는 결과

화면 요약에 기간 매출, 직접 비용, 날짜별 비용, 손익을 표시합니다. 디자인 시안의 대시보드에는 총매출, 직접 재료원가, 공헌이익, 일일 비용, 순추정 영업이익 카드와 판매 채널별 비중이 보입니다. 세부 비용 항목과 채널 분류는 데이터 기준 확정 후 적용합니다. MVP에서 손익 파일을 내려받는 기능은 없습니다.

#### 오류나 예외가 있을 때의 동작

- 기간에 기록이 없으면 ‘기록 없음’으로 표시하고 실제 0원과 구분합니다.
- 미마감 날짜가 포함되면 결과를 실제 마감 실적으로 오해하지 않도록 누적 상태를 표시합니다.
- 월 계획과 날짜별 비용이 둘 다 존재하는 향후 가져오기 상황에서도 두 표현을 더하지 않습니다.
- 특정 비용이나 레시피 계산에 필요한 정보가 부족하면 총액에 조용히 0으로 포함하지 않고 누락 항목을 표시합니다.
- 주의 시작 요일, 월·분기·반기·연도 경계는 미정입니다.

#### 직접 확인할 방법

순매출 8,000원, 직접 비용 1,500원, 날짜별 비용 1,000원을 기록하고 화면 손익이 5,500원인지 확인합니다. 월 계획 금액을 따로 넣어도 이미 입력된 날짜별 비용이 중복 증가하지 않는지 확인합니다. 미마감 날짜가 포함된 기간은 ‘0원 실적’이 아니라 ‘미마감’으로 보이는지 확인합니다.

### 6. 재료 입고·폐기·실사와 잔량

#### 사용자가 하는 일

‘재료 입고/실사’ 또는 기간 화면의 ‘입고 / 폐기 / 실사 등록’을 눌러 재료와 변동 종류를 선택합니다. 입고량·폐기량 또는 실제로 센 재고 수량, 사유를 입력합니다.

#### 입력

- 대상 재료, 변동 종류(입고·폐기·실사), 단위 수량, 사유, 날짜.
- 시안의 예시 재료는 원두, 우유, 콜드브루 원액, 시럽, 자몽청, 탄산수, 말차, 버터, 밀가루, 크림치즈, 포장 컵입니다.
- 제안 입력 기준: 입고·폐기는 양의 수량을 입력하고 종류에 따라 자동으로 증감 부호를 적용합니다. 실사는 이론 조정량이 아니라 실제 센 재고량을 입력하고 차이를 계산합니다. 이 기준은 시안의 “실제 계측값” 안내 및 첨부 자료의 counted_quantity 구조에 맞춘 제안입니다.

#### 프로그램이 하는 일

잔량 계산 제안은 다음과 같습니다.

- 이론 잔량 = 기초 재고 + 입고 − 레시피에 따른 판매 사용량 − 폐기 ± 실사 조정
- 예: 기초 100g, 입고 50g, 판매 사용 20g, 폐기 3g이면 이론 잔량은 127g입니다. 실제로 122g을 세었다면 실사 조정은 −5g이고, 조정 후 잔량은 **122g**입니다.
- 판매 차감은 메뉴의 적용 레시피 버전·채널을 따릅니다. 포장 전용 재료는 포장 판매에서만 차감합니다.
- 실사 입력은 현재 이론 잔량과 비교하여 조정 차이를 기록합니다. 같은 실사값을 반복 입력해 조정이 두 번 적용되지 않도록 합니다.
- 안전재고 미달 표시와 발주 참고량은 수업 후 확장입니다. 수업 MVP의 잔량 숫자·입출고 내역을 먼저 제공합니다.

#### 화면과 파일에 나오는 결과

재료별로 단위, 기초 재고, 입고, 판매 차감, 폐기, 실사 조정, 현재 잔량, 상태를 표로 표시합니다. 안전재고 관련 기준이 입력되어 있을 때 부족 상태를 표시할 수 있으나, 실제 발주량 제안은 확장 범위입니다. 재고 파일 출력은 MVP에 없습니다.

#### 오류나 예외가 있을 때의 동작

- 수량이 비어 있거나, 음수·단위가 대상 재료와 맞지 않으면 저장하지 않고 입력 오류를 표시합니다. 폐기 부호는 선택된 변동 종류가 적용하므로 수동 부호를 다시 입력하게 하지 않는 것이 제안 기준입니다.
- 재고 차감 뒤 이론 잔량이 음수가 되면 판매 입력 자체를 지우지 않고 부족 경고와 음수 잔량을 표시하는 것이 제안 기준입니다. 실제 판매를 기록해야 하는 상황을 가리지 않기 위한 제안이며, 음수 허용 여부는 미정입니다.
- 실사값은 0일 수도 있으므로 빈칸과 0을 구분합니다. 음수 실사 수량은 허용하지 않습니다.
- 시안은 kg·캔·세트도 보이고 PRD 자료는 g·ml·개를 사용합니다. 변환 용량이 확인되지 않은 단위는 자동 변환하지 않고 입력을 보류하거나 단위 확인을 안내해야 합니다. 디자인 단위와 저장 기준 단위 변환표는 미정입니다.
- 레시피 또는 재료가 연결되지 않으면 해당 차감만 누락 사유로 표시하고 전체 잔량이 정확한 것처럼 표시하지 않습니다.

#### 직접 확인할 방법

100g 기초, 50g 입고, 20g 판매 사용, 3g 폐기, 실제 실사 122g을 입력합니다. 이론값 127g, 조정 −5g, 최종 122g이 화면에 표시되는지 확인합니다. 메뉴와 채널을 바꾸면 적용 대상이 아닌 재료는 차감되지 않는지 확인합니다.

### 7. 일일 마감 검토·확정·전표 출력

#### 사용자가 하는 일

대시보드의 ‘오늘 마감 확정’을 눌러 판매·비용·메뉴 분석·재고 확인 내용을 검토합니다. ‘마감 전표 인쇄’ 후 ‘네, 마감 전표 생성 및 확정’을 눌러 마감합니다. ‘더 검토하기’를 누르면 마감하지 않고 화면으로 돌아갑니다.

#### 입력

선택된 마감 일자와 해당 일자의 저장된 판매·비용·재고 기록이 사용됩니다. 사용자가 확인 버튼을 누르는 것이 확정 입력입니다.

#### 프로그램이 하는 일

- 마감 전 요약 금액과 완료 단계, 재고 상태를 보여줍니다.
- 확정 시 해당 일자의 판매·비용을 잠그고, 최종 재고 잔량을 다음 날짜의 기초 재고로 이월합니다.
- 확정된 마감 전표를 인쇄 가능한 결과로 제공합니다. 전자 파일 형식은 미정입니다.
- 확정 뒤 잠긴 일자의 기록을 바꿀 수 없게 합니다. 마감 취소·재개·과거 기록 정정 기능은 시안과 PRD에 정의되어 있지 않아 범위에 넣지 않습니다.

#### 화면과 파일에 나오는 결과

확인 화면에 일자별 매출, 메뉴 직접 비용, 날짜별 비용, 손익, 판매 차감 완료 여부, 실사 검토 결과와 재고 주의를 표시합니다. 확정 뒤 완료 상태와 마감 전표를 보여줍니다. 인쇄 결과의 PDF 여부나 저장 위치는 정하지 않습니다.

#### 오류나 예외가 있을 때의 동작

- 저장 중인 미완성 입력이 있거나 계산할 수 없는 핵심 기록이 있으면 누락 항목을 보여주고 확정을 보류하는 것이 제안 기준입니다.
- 안전재고 미달은 확인 경고로 표시합니다. 시안처럼 경고를 확인한 뒤 마감할 수 있는지를 포함한 경고 무시 정책은 미정입니다.
- 이미 마감된 날짜를 다시 확정하려 하면 중복 전표를 만들지 않고 이미 완료된 상태를 안내합니다.
- 전표 출력에 실패하더라도 마감 확정 여부와 전표 상태를 분명히 표시해야 합니다. 확정 뒤 재인쇄 허용 여부는 미정입니다.
- 마감 후 수정·삭제 요청에는 저장하지 않고 ‘마감된 날짜의 기록’임을 안내합니다.

#### 직접 확인할 방법

열린 날짜의 판매·비용·재고를 입력한 뒤 검토 화면에서 합계와 누락을 확인합니다. 취소 시 상태가 바뀌지 않는지, 확정 시 일자가 잠기고 다음 날 기초 재고로 잔량이 이월되는지 확인합니다. 같은 날짜를 두 번 마감해 중복 전표가 생기지 않는지 확인합니다.

### 8. 저장 및 기본 입력 검증

#### 사용자가 하는 일

판매·비용·재고 기록을 저장하고 화면을 나갔다가 다시 엽니다.

#### 입력

각 기능에서 입력한 일자, 숫자, 선택 항목과 기록 내용입니다.

#### 프로그램이 하는 일

성공한 기록은 영속 저장하고, 이후 조회와 계산에 같은 기록을 반영합니다. 저장 방식이나 기술은 이 문서에서 정하지 않습니다.

#### 화면과 파일에 나오는 결과

저장 성공 여부와 바뀐 기록 목록·요약값을 보여줍니다. 수업 MVP에는 별도 백업 파일을 만들지 않습니다.

#### 오류나 예외가 있을 때의 동작

- 필수 입력 누락, 날짜 형식 오류, 잘못된 수량·금액, 없는 메뉴·재료 참조를 검증하고 저장하지 않습니다. 어떤 항목을 고쳐야 하는지 표시합니다.
- 저장 실패 시 성공 메시지를 표시하지 않고 입력값을 보존해 재시도할 수 있게 합니다.
- 빈칸은 미입력으로, 숫자 0은 실제 0으로 처리합니다.
- 네트워크·브라우저·저장 수단별 동작은 기술 결정이므로 요구하지 않습니다.

#### 직접 확인할 방법

기록을 저장한 뒤 화면을 다시 열어 같은 행과 합계가 있는지 확인합니다. 필수값을 비운 상태, 잘못된 날짜, 음수 판매 수량을 각각 제출해 저장되지 않고 수정 안내가 나오는지 확인합니다.

## 수업 후 확장 기능

### 9. 분기·반기·연간 조회

#### 사용자가 하는 일

기간 선택에서 분기·반기·연간을 고릅니다.

#### 입력

기간 종류, 기준 연도와 조회 대상 기록입니다.

#### 프로그램이 하는 일

수업 MVP의 손익 계산 기준을 그대로 사용해 긴 기간의 실제 실적을 집계합니다. 분기·반기 경계는 미정이므로 달력 기준을 임의 확정하지 않습니다.

#### 화면과 파일에 나오는 결과

기간 매출·직접 비용·날짜별 비용·손익 요약과 메뉴·재고 집계를 표시합니다. 부분 연도는 전체 연간 실적처럼 보이지 않도록 실제 포함 기간을 함께 표시합니다. 별도 파일 출력은 엑셀 확장 기능에 포함될 때 정합니다.

#### 오류나 예외가 있을 때의 동작

자료가 일부 기간만 있으면 부분 기간임을 표시합니다. 시작일·종료일에 마감 누락이 있으면 미마감으로 표시하고 0원으로 채우지 않습니다.

#### 직접 확인할 방법

연간 범위에 기록이 일부 월만 있을 때 표시되는 포함 기간을 확인하고, 각 월 결과를 더한 합과 연간 누계가 일치하는지 확인합니다.

### 10. 예상 손익

#### 사용자가 하는 일

예상 손익 확장 화면에서 대상 기간의 현재 누계와 예상 기간 결과를 조회합니다.

#### 입력

현재까지의 실제 판매·직접 비용·날짜별 비용, 영업 달력, 남은 영업일을 사용합니다. 정확한 전망 정책은 미정입니다.

#### 프로그램이 하는 일

제안 방식은 마감된 영업일의 일평균 실적을 남은 예정 영업일에 적용하는 것입니다. 이는 전망 예시일 뿐 확정 계산 기준이 아닙니다.

- 예: 2일 영업 후 순매출 20,000원, 직접 비용 4,000원, 날짜별 비용 2,000원이고 총 4일 영업 예정이면, 1일 평균은 순매출 10,000원·직접 비용 2,000원·비용 1,000원입니다. 4일 예상 손익은 매출 40,000원 − 직접 비용 8,000원 − 비용 4,000원 = **28,000원**입니다.
- 날씨·요일·계절·메뉴별 차이를 반영할지, 미래 날짜의 비용을 어떻게 추정할지는 미정입니다.

#### 화면과 파일에 나오는 결과

실제 누계와 예상 기간 전체 결과를 구분해 보여줍니다. 예측을 실제 기록이나 마감 금액으로 표시하지 않습니다. 예상 손익의 별도 파일 출력은 미정입니다.

#### 오류나 예외가 있을 때의 동작

완료 영업일이 없거나 남은 영업일을 알 수 없으면 예상치를 만들지 않고 자료 부족 사유를 표시합니다. 미마감 날짜를 영업 실적 0일로 사용하지 않습니다.

#### 직접 확인할 방법

예시의 2일 누계와 4일 영업 예정값을 넣어 제안 방식에서 28,000원이 나오는지 계산기로 확인합니다. 실제 누계와 예상치가 서로 다른 표시로 구분되는지도 확인합니다.

### 11. 엑셀 양식 내려받기와 기록 가져오기

#### 사용자가 하는 일

판매·비용 입력용 엑셀 양식을 내려받아 행을 작성하고, 완성한 파일을 가져옵니다.

#### 입력

판매는 일자·채널·메뉴·레시피 버전·수량 및 최종 합계에 필요한 실제 금액 정보, 비용은 일자·구분·항목·금액을 담는 것이 제안입니다. 정확한 열 목록과 기준 정보 파일 포함 여부는 미정입니다.

#### 프로그램이 하는 일

가져오기 전 파일을 검증하고 행별 문제를 안내합니다. 첨부 Excel과 JSON은 같은 기록이라는 안내를 보여주고 같은 기록을 두 번 가져오지 않도록 중복 확인을 제안합니다. 전체 파일을 한 번에 확정할지, 오류 행만 제외할지는 미정입니다.

#### 화면과 파일에 나오는 결과

사용자는 내려받을 수 있는 엑셀 양식 파일을 받습니다. 가져오기는 처리 건수와 실패 행·원인을 화면에 보여줍니다. 가져온 기록은 판매·비용 목록과 분석 결과에 반영됩니다.

#### 오류나 예외가 있을 때의 동작

잘못된 형식, 필수 열 누락, 날짜·금액 오류, 미등록 메뉴·채널·레시피, 중복 가능성이 있으면 파일명과 행·열을 포함해 안내합니다. 시안 데모와 첨부 원자료의 메뉴·채널·단위가 다르므로 매핑표 없이 이름을 자동 변환하지 않습니다.

#### 직접 확인할 방법

양식을 내려받아 정상 1행과 잘못된 1행을 포함한 파일을 가져옵니다. 정상 기록만 의도한 방식으로 반영되고 오류 행이 식별되는지 확인합니다. 같은 파일을 다시 가져올 때 중복 방지 정책대로 동작하는지 확인합니다.

### 12. 백업과 복원

#### 사용자가 하는 일

사용자가 전체 데이터를 백업 파일로 저장하거나 백업 파일을 선택해 복원합니다.

#### 입력

복원할 백업 파일과 복원 실행 확인이 입력입니다. 파일 형식, 복원 때 현재 기록을 교체할지 병합할지는 미정입니다.

#### 프로그램이 하는 일

판매·비용·메뉴·재료·레시피·재고·마감 정보 등 복원 대상 범위를 포함한 백업을 만듭니다. 복원 전 파일을 검증하고 기존 데이터와 충돌 가능성을 알립니다.

#### 화면과 파일에 나오는 결과

백업 성공 시 파일을 내려받고 생성 시점을 안내합니다. 복원 결과에는 처리 상태와 복원 대상 범위를 표시합니다.

#### 오류나 예외가 있을 때의 동작

손상·잘못된 형식·지원하지 않는 버전이면 기존 데이터를 바꾸지 않고 실패 이유를 안내합니다. 병합·전체 교체·마감 기록 충돌 정책은 미정이며 복원 중 조용히 덮어쓰지 않습니다.

#### 직접 확인할 방법

백업 후 새 기록을 추가하고 백업을 복원해 선택된 정책대로 이전 상태가 돌아오는지 확인합니다. 손상된 파일을 넣었을 때 기존 데이터가 유지되는지 확인합니다.

### 13. 재료 부족·발주 참고량

#### 사용자가 하는 일

재료 잔량과 공급사 납기·안전 재고 정보를 보고 발주 참고량을 확인합니다. 실제 발주는 사용자가 별도로 판단합니다.

#### 입력

현재 잔량, 레시피 판매 사용량, 납기일수, 안전 재고 일수입니다. 첨부 자료의 납기·안전 재고 일수는 영업일 단위지만, 디자인 데모 목록에는 일부 값이 없어 기준 정보가 필요합니다.

#### 프로그램이 하는 일

제안 기준은 평균 일일 사용량에 납기일과 안전 재고일을 반영한 필요량에서 현재 잔량을 뺀 값입니다. 0보다 작으면 발주 참고량은 0으로 표시합니다.

- 예: 평균 사용 20개/영업일, 납기 2영업일, 안전 재고 2영업일이면 기준 필요량은 80개입니다. 현재 50개라면 참고량은 **30개**입니다.
- 판매 전망 기간과 납기·안전 재고 반영 기준은 승인 전 제안입니다. 자동 발주나 공급사 전송은 하지 않습니다.

#### 화면과 파일에 나오는 결과

재료별 현재 잔량, 부족 경고, 제안 발주 수량을 표시합니다. 별도 발주 파일이나 주문 전송은 이 기능에 포함하지 않습니다.

#### 오류나 예외가 있을 때의 동작

재료 사용량·납기·안전 재고 중 기준이 빠져 있으면 추측 발주량을 보여주지 않고 ‘기준 입력 필요’를 표시합니다. 마감되지 않은 미래 판매를 사용 실적으로 계산하지 않습니다.

#### 직접 확인할 방법

예시의 20개/영업일, 2일 납기, 2일 안전 재고, 현재 50개를 넣어 30개가 표시되는지 확인합니다. 납기 정보가 비어 있으면 숫자 대신 기준 입력 필요가 표시되는지 확인합니다.

## PRD·시안 차이 및 미정 사항

- 요청된 PRD 경로와 실제 파일 경로가 다릅니다. 현재 파일은 `data/docs/docs_PRD.md`입니다.
- 이번 시작 자료를 시안 예시로 정했으므로, 시안의 현재 메뉴·재료·채널 목록을 데모로 사용합니다. 이후 첨부 원자료 Excel을 가져올 때 두 데이터의 메뉴 ID, 채널, 재료 ID를 연결하는 방식은 정하지 않았습니다.
- 시안 재료의 kg·캔·세트 단위와 첨부 자료의 g·ml·개 단위 간 환산 기준이 필요합니다. 환산량을 모르는 값은 자동 변환하지 않는 것이 제안입니다.
- 시안 비용 입력란에 보이는 결제 수단·영수증 첨부, 비용 구분 목록은 PRD 승인 범위가 아닙니다. 필요 여부와 분류 목록은 정해야 합니다.
- 시안은 월세·급여를 월 계획에서 나눠 반영하라고 안내하지만, 사용자는 실제 손익에 날짜별 비용 기록만 사용하기로 했습니다. 시안 안내 문구를 바꿀지 결정이 필요합니다.
- 새 판매의 실제 단가·할인·결제 수수료 입력, 메뉴 레시피 가격 기준과 버전이 바뀌는 시점은 제안으로 남아 있습니다.
- 재료 구매를 비용 기록과 재고 입고에 함께 남길 경우 이중 계산을 막을 처리 방식, 실사 후 음수 재고 허용, 재고 부족 상태에서 판매 저장 허용 여부는 미정입니다.
- 일일 마감은 포함하기로 했지만, 낮은 재고 경고가 마감을 막는지, 출력 실패 후 재인쇄할 수 있는지, 마감된 기록을 정정할 수 있는지는 시안·PRD로 확정되지 않았습니다.
- 주간 시작 요일, 분기·반기·연간 기준, 예상 손익과 발주 참고량의 세부 계산 기준은 제안일 뿐입니다.
- 엑셀 가져오기에서 오류 행을 제외하고 일부 반영할지 전체를 보류할지, 반복 가져오기 중복 정책, 백업 복원 시 교체·병합 정책은 미정입니다.
- 이 문서는 기능 동작과 입력·출력·오류를 정리합니다. 기술, 화면 시각 설계, 세부 코드·구현 방식을 정하지 않습니다.
