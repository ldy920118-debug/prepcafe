# 기술 요구사항 문서 (TRD)

**문서 상태:** 기술 기준안. 사용자가 추천안에 동의한 Next.js 16.x 업그레이드를 반영했습니다. PRD·FRD에서 정하지 않은 계산 기준과 새 기능은 확인 필요로 남겼습니다.

**참고 문서:** [PRD](../data/docs/docs_PRD.md), [FRD](02_FRD.md), 시안의 `data/design/stitch_cafe_daily_closing_app/` 파일

> 요청된 `docs/01_PRD.md`는 현재 없으므로 실제 PRD인 `data/docs/docs_PRD.md`를 기준으로 했습니다.

## 사용할 기술과 선택 이유

### 기술 선택

| 구분 | 제안 | 이유·상태 |
|---|---|---|
| 웹 앱 | 현재 프로젝트의 Next.js App Router, React, TypeScript, Tailwind를 이어 사용 | 기존 프로젝트 구성 재사용. 현재 설치된 Next.js 14는 공식 지원 목록에서 제외되어 있어, 사용자가 추천안을 선택한 대로 운영 전 지원 중인 Next.js 16.x로 올립니다. 정확한 패치 버전은 개발 시작 시점의 최신 보안 패치로 고정합니다. [Next.js 지원 정책](https://nextjs.org/support-policy) |
| 데이터베이스 | Supabase PostgreSQL | 판매·비용·재고·레시피 사이의 관계를 보존하고, 날짜·메뉴·재료별 조회에 적합합니다. 기록의 원본은 이 데이터베이스 하나로 둡니다. |
| 사용자 인증·접근 제한 | Supabase Auth와 RLS(행 단위 접근 제한) 제안 | 인터넷에 배포하는 매장 기록을 보호하기 위한 권고입니다. 로그인은 PRD·FRD에서 기능으로 확정되지 않았으므로, 구현 전에 사용자 승인이 필요합니다. [Supabase Auth](https://supabase.com/docs/guides/auth), [RLS](https://supabase.com/docs/guides/database/row-level-security) |
| 코드 보관·배포 | GitHub와 Vercel | 사용자가 지정한 배포 방향입니다. 현재 작업 폴더에는 Git 저장소가 확인되지 않아 GitHub 연결은 별도 설정이 필요합니다. 비공개 저장소를 권장하지만 공개 여부는 미정입니다. |

### 범위와 계산 원칙

- 수업 MVP는 판매·비용 기록 직접 입력·수정·삭제, 메뉴 직접 비용 수익성, 일·주·월 실제 손익, 재료 입고·폐기·실사 및 잔량, 영속 저장, 승인된 일일 마감·전표 출력입니다.
- 수업 후 확장은 예상 손익, 엑셀 양식 내려받기·기록 가져오기, 백업·복원, 발주 참고, 분기·반기·연간 조회입니다.
- 메뉴 수익성에는 재료·포장·결제 관련 메뉴 직접 비용만 두고, 임차료·인건비 같은 날짜별 공통 비용은 전체 손익에만 반영합니다. 실제 손익에는 날짜별 비용 기록만 사용하며 월 비용 계획을 다시 합산하지 않습니다.
- 계산은 FRD의 확인된 기준을 바꾸지 않습니다. FRD에서 제안 또는 미정으로 남긴 판매 단가·할인·수수료, 재료 가격의 원가 기준, 레시피 변경 시점, 단위 변환, 음수 재고 허용 등은 임의로 확정하지 않습니다. 해당 항목을 확정하기 전에는 관련 계산을 정확한 값처럼 표시하지 않습니다.

### 속도·비용 고려

- 첨부 자료에는 판매 6,112건과 재고 기록 1,515건 등이 있지만, 사용자가 선택한 대로 이 과거 이력은 초기 앱에 미리 채우지 않습니다. 이 규모는 처리량 참고치로만 사용합니다.
- MVP에서는 날짜 범위와 메뉴·재료 조건으로 필요한 기록만 조회하고, 반복 집계가 필요한 날짜·메뉴·재료 열에 데이터베이스 색인을 둡니다. 이 규모에서 별도 분산 서버나 별도 분석 시스템은 제안하지 않습니다.
- 정확한 응답 시간 목표는 정해지지 않았습니다. 대표 자료량으로 조회 속도를 확인한 뒤 수치 목표를 정합니다.
- 현재 공개 요금 안내 기준 Vercel Pro는 월 USD 20부터이고, Supabase Pro는 월 USD 25부터입니다. 기본 합계는 월 USD 45부터이며 세금·초과 사용료는 별도입니다. Supabase Pro는 일일 자동 백업을 7일 보관합니다. 별도 미리보기 데이터베이스를 추가하면 추가 비용이 생길 수 있습니다. Vercel Hobby는 상업적 사용이 제한되어 매장 운영 배포에는 Pro 이상이 필요합니다. [Vercel 요금](https://vercel.com/pricing), [Vercel 상업적 사용 기준](https://vercel.com/docs/limits/fair-use-guidelines), [Supabase 요금·백업](https://supabase.com/pricing)

## 처리 순서

1. 사용자가 운영 화면에 접근합니다. 로그인은 보안 권고지만, PRD·FRD에 없는 기능이라 승인 전에는 구현 범위로 확정하지 않습니다.
2. 시작 자료는 시안의 예시만 사용합니다. 첨부 Excel과 JSON의 판매 이력은 불러오지 않습니다. 시안의 일부 합계와 행별 값이 맞지 않으므로 검증에 쓸 일관된 데모 기록은 확정이 필요합니다.
3. 사용자가 판매 기록을 입력·수정·삭제합니다. 프로그램은 입력값과 날짜의 마감 여부를 확인한 뒤 저장하고, 확정된 계산 기준으로 메뉴 수익성·기간 손익·재고 결과를 갱신합니다.
4. 사용자가 날짜별 비용을 입력·수정·삭제합니다. 저장된 날짜의 실제 손익만 갱신하며 월 비용 계획을 중복 합산하지 않습니다.
5. 사용자가 재료 입고·폐기·실사 수량을 기록합니다. 프로그램은 기록을 보존하고 확정된 재고 규칙에 따라 잔량을 표시합니다.
6. 사용자는 일·주·월 조회와 메뉴 수익성을 확인하고, 일일 마감 시 해당 날짜의 기록과 재고 상태를 검토합니다.
7. 사용자가 마감을 확정하면 해당 날짜를 잠그고 재고를 다음 날로 이월하며 전표를 인쇄할 수 있게 합니다. 잠금과 이월은 한 작업으로 함께 성공하거나 함께 실패해야 합니다.

## 주요 파일이 맡는 일

아래 경로는 구현 시 권장하는 역할이며, 이번에는 코드를 만들지 않습니다.

- **src/app/**: 현재 Next.js 앱의 화면과 페이지 이동. 기존 공개 사이트와 운영 화면을 같은 앱에 둘지 별도 앱으로 나눌지는 미정이며, 기존 앱 재사용을 권장합니다.
- **src/lib/domain/**: FRD에서 최종 확정된 계산과 입력값 검증. 계산을 화면별로 복제하지 않고 한곳에서 관리합니다.
- **src/lib/server/**: 서버에서 로그인 확인, 데이터 읽기·쓰기, 저장 실패 처리 담당.
- **supabase/migrations/**: 데이터베이스 구조, 필수 제약, 접근 제한 변경 이력 담당.
- **supabase/seed.sql**: 승인된 시안 데모 자료만 준비. 첨부 판매 이력은 넣지 않습니다. 계산 검증에 쓸 데모 값은 시안 내부 불일치 해소 후 정합니다.
- **tests/**: 계산 예시, 저장 후 재조회, 기간 조회, 마감·재고 이월, 접근 제한과 오류 처리를 확인합니다.
- **.env.example**: 필요한 환경 변수 이름만 문서화합니다. 실제 키와 비밀번호는 기록하지 않습니다.

## 데이터 저장·이동·복구

- **MVP 저장:** 브라우저 임시 저장만을 원본으로 쓰지 않고 PostgreSQL에 영속 저장합니다. 거래 날짜는 날짜 값으로, 생성·수정 시각은 별도 시각 값으로 보존합니다. 원화 금액은 정수, 수량은 단위와 함께 저장하며 빈 값과 0을 구분합니다.
- **수정·삭제·마감:** 판매·비용·재고 기록 변경은 부분 저장이 생기지 않도록 데이터베이스 작업 단위로 처리합니다. 마감 확정 시 날짜 잠금과 재고 이월도 같은 작업 단위로 처리합니다.
- **엑셀 가져오기·양식:** 수업 후 확장입니다. 향후 파일을 저장하기 전에 행별 형식·필수값·참조 항목을 검증하고 오류 행을 보여주는 방식을 권합니다. 첨부 Excel과 JSON은 같은 자료이므로 둘 다 가져오지 않습니다. 반복 가져오기에서 중복을 거부할지 건너뛸지는 미정입니다.
- **백업·복원:** 수업 후 확장입니다. 버전이 포함된 전체 데이터 JSON 파일을 내려받는 방식을 권합니다. 복원 전 파일 검증과 현재 상태 보호 절차를 두는 것을 권하지만, 기존 자료를 덮어쓸지 합칠지는 미정입니다. 공급자 자동 백업은 장애 복구용이며 사용자가 직접 내려받고 복원하는 기능을 대체하지 않습니다.
- 영수증 사진 등 PRD·FRD에서 제외한 파일 첨부는 저장하지 않습니다.

## 정보 보호

- 매출·비용·재고 자료를 GitHub에 넣지 않습니다. 저장소가 공개될 경우를 고려해 실제 환경 값과 실제 운영 데이터는 코드·시드 파일·로그에 포함하지 않습니다.
- 데이터베이스 키와 비밀번호는 Vercel 환경 변수에 보관하고 브라우저 코드에 노출하지 않습니다. 로컬·미리보기·실서비스 환경의 키를 분리합니다.
- 로그인과 RLS를 적용하는 안을 권합니다. 로그인 없는 공개 배포는 매장 운영 자료를 보호하기 어렵기 때문에 승인 전까지 출시 가능 상태로 간주하지 않습니다.
- 미리보기 배포에는 가상 자료만 연결하고, 실제 자료의 접근권한은 필요한 사용자로 제한합니다. 개인 고객 정보는 PRD·FRD 범위에 없으므로 수집하지 않습니다.

## 오류 대응

- 날짜·수량·금액의 형식이나 범위가 잘못되면 저장하지 않고 해당 항목을 안내합니다. 정확한 허용 범위는 FRD 미정 입력 규칙을 확인한 뒤 정합니다.
- 네트워크나 데이터베이스 저장이 실패하면 성공으로 표시하지 않습니다. 입력값을 화면에 유지하고 저장되지 않았음을 알려 재시도할 수 있게 합니다.
- 하나의 작업이 중간에 실패하면 기록 일부만 반영되지 않도록 처리합니다. 재시도 때문에 같은 판매나 마감이 중복 생성되지 않도록 중복 방지 기준을 둡니다.
- 계산에 필요한 레시피·단위·가격 정보가 없으면 0원으로 조용히 처리하지 않고 계산 확인 필요 상태로 알립니다. 판매 저장 자체를 허용할지는 FRD 미정 사항입니다.
- 잠긴 날짜의 수정·삭제 요청은 거부하고 잠금 상태를 안내합니다. 인쇄 실패 시 마감 상태와 인쇄 상태를 구분합니다. 확정 후 재인쇄 허용 여부는 미정입니다.

## 배포 방법

- GitHub 저장소에 코드를 보관하고 Vercel을 연결합니다. 현재 작업 폴더에는 Git 저장소가 확인되지 않아 저장소 생성·연결이 선행되어야 합니다. 비공개 저장소를 권장하지만 공개 여부는 미정입니다.
- 작업 브랜치와 PR은 미리보기 배포로 확인하고 운영 브랜치만 실서비스로 배포합니다. 배포 환경별 비밀 값과 데이터베이스를 구분합니다. [Vercel Git 배포](https://vercel.com/docs/git), [배포 환경](https://vercel.com/docs/deployments/environments)
- 실서비스에는 상업적 사용 조건에 맞는 Vercel 요금제를 사용합니다. Supabase Pro는 자동 백업과 비활성 일시 중지 없음이 제공되어 운영 환경에 권장됩니다. 요금제와 추가 미리보기 데이터베이스 비용은 실제 계정 설정 전에 확인합니다.

## 확인 방법

- 구현한 모든 계산은 FRD의 손계산 예시와 일치하는지 자동 검증하고, 기간 조회는 날짜 경계와 미마감 날짜를 포함해 확인합니다. FRD에서 계산 기준이 미정인 항목은 임의 기대값을 만들지 않습니다.
- 판매·비용·재고 입력·수정·삭제 후 페이지를 다시 열어도 저장 결과가 남는지 확인합니다.
- 메뉴 수익성, 일·주·월 손익, 날짜별 비용 기준, 재고 잔량이 같은 원본 기록으로 일관되게 계산되는지 확인합니다. Excel과 JSON 동일 이력을 두 번 합산하지 않는지 향후 가져오기 검증에 포함합니다.
- 마감 전표의 합계, 확정 후 잠금, 다음 날 재고 이월, 중복 마감 방지와 인쇄 실패 안내를 확인합니다.
- 로그인 승인 시 비로그인 접근 차단, 계정 간 자료 격리, 비밀 값의 브라우저·저장소 미노출을 확인합니다.
- 운영 배포 전에 첨부 자료 규모를 참고한 조회 속도와 실제 비용 사용량을 측정합니다. 수치 목표는 별도 합의 전까지 확정하지 않습니다.

## 미정 사항과 확인 필요

- 메뉴 수익성 및 새 판매 기록의 구체 원가 기준, 단가·할인·수수료 필드와 재료 가격 이력 적용 기준
- 주간 경계, 기간 귀속 경계, 미마감 판정 세부 기준
- 레시피 단위와 시안의 kg·캔·세트 표기 간 변환, 실사 후 잔량 계산 및 음수 재고 허용 여부
- 판매에 필요한 계산 자료가 없을 때 저장을 허용할지 여부
- 비용 구분 목록과 재료 구매 비용·재고 입고 간 중복 방지 기준
- 마감 경고를 무시할 수 있는 조건, 확정 후 전표 재인쇄 조건
